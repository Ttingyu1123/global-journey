## 一、工程品質（最嚴重的面向）

### 1. 【Critical】Vercel 部署繞過型別檢查 — 生產路徑的假綠燈
- `vercel.json` 的 `buildCommand` 是 `npx vite build`，覆蓋掉 `package.json` 的 `"build": "tsc && vite build"`。
- 本地 `npm run build` 會過 tsc；**Vercel 部署完全不跑 tsc**，只要 esbuild 能轉譯就上線。
- 型別錯誤只在本地被抓，push 上去照樣部署成功。
- Falsification：若 Vercel dashboard 手動改回 build script 則不成立——需到 dashboard 確認。

### 2. 【High】零測試 + 零 CI + 零 lint
- 無 `*.test.ts`、無 test runner、無 `test` script。覆蓋率 0%。
- `.github/workflows/` 不存在。無 pre-commit hook。
- 無 eslint/prettier/biome 任何設定。
- 三者疊加：任何回歸完全靠肉眼。

### 3. 【Medium】零 code splitting，「lazy init」宣稱誤導
- 單一 JS chunk 310.55 kB（gzip 89.07 kB），`grep "import("` 全 repo 零筆——沒有任何 dynamic import。
- Leaflet + markercluster + 97 筆地標（609 行）全部靜態打進主 bundle。
- CLAUDE.md 說的「Leaflet lazy init」只是延遲建立地圖**實例**（解 DOM timing），函式庫 JS/CSS 頁面載入當下就全部下載了。文件與實作不一致。
- `public/MAP.png` 2.8MB 佔 dist 總大小 3.2M 的絕大部分。

### 正面（有證據）
- `tsconfig.json` `strict: true`，非 solution-style，`tsc --noEmit` 真的檢查了 21 個檔案（非 no-op）。
- 型別逃逸：`: any` / `as any` / `@ts-ignore` / non-null `!` 全部 **0 處**。
- 唯一的 catch block（`AiGenerator.ts:46`）處理正確：`unknown` + instanceof 收窄 + escapeHtml + 對用戶顯示。
- Repo 乾淨無 debris，3 個 prod 依賴全被使用，npm audit 0 vulnerabilities。
- 缺口：`noUnusedLocals` / `noUnusedParameters` 未開（開了就會抓到下面架構篇的未使用 import）。

## 二、架構

### 1. 【High】半成品「歷史紀錄」功能：寫入永遠讀不回來
- `db.ts` 的 `getHistory()`、`deleteHistoryItem()`、`isBookmarked()` — 0 呼叫者。
- `AiGenerator.ts:36` 有呼叫 `saveToHistory` 寫入 IndexedDB，但**沒有任何 UI 讀出顯示**——資料進得去、出不來。
- 孤兒型別：`SavedCollection`（types/index.ts:30）、`RouteItem`（types/index.ts:47）零引用；收藏實作已分岔成 `Set<number>`。
- `MapView.ts:123` `flyToLandmark()` 0 呼叫者；`RoutePlanner.ts:2` import 了 `copyToClipboard` 從未使用。
- 危險在於誤導：維護者會以為歷史功能已完成。

### 2. 【Medium】複製按鈕邏輯 5 處逐字重複（約 39 行）+ prompt 樣板 7 處重複（約 70 行）
- `CardGrid.ts:120-125,137-145`、`VideoTransition.ts:44-52`、`StylePicker.ts:64-69`、`AiGenerator.ts:76-84` — 完全相同的 `copyToClipboard().then(class 切換+文案+toast+setTimeout(2000) 還原)` 結構，magic number `2000` 出現 5 次。
- 抽 `bindCopyButton()` + `renderPromptSection()` 兩個 helper 即可收斂 100+ 行。

### 3. 【Medium】MapView 直接操作 CardGrid 的 DOM（唯一的封裝破口）
- `MapView.ts:110-119` 直接 `document.querySelector('.card[data-id=...]')` + `classList.add('open')`，繞過 CardGrid 所有 export。
- CardGrid 改展開機制時 MapView 會悄悄失效，編譯期抓不到。其餘元件都守 getter/callback 紀律，只有這一處。

### 4. 【Low】同一份資料兩套 prompt 生成邏輯並存
- `style-composer.ts` 已證明「地標特徵+風格模板→組合」可行（4 個非預設風格用它），但預設 3d-relief 風格仍走 `landmark.promptEn` 寫死字串。
- id 2/3/4 的 `promptEn` 逐字比對：句型骨架重複率 >70%（"3D relief model of"、"on an aged blueprint"、"--ar 16:9 --style raw" 全部逐字重複）。
- 注意：模板化前需人工確認不犧牲手工精修的文案品質。

### 5. 【Low】API 邊界隱性 any
- `gemini.ts:36,40` `resp.json()` 回傳隱性 any，`:43` `JSON.parse(cleaned) as GenerateResult` 是斷言非驗證——Gemini 回傳格式跑掉時執行期才爆炸。

## 三、安全

### 現況：無現存漏洞，但零縱深防禦

- **XSS 面全數逐一核對通過**：AiGenerator/CardGrid/VideoTransition/StylePicker/RoutePlanner/ContinentBar/MapView 所有動態插值（含 Gemini AI 回傳、Leaflet popup）都經 `escapeHtml()`。
- **無 committed secrets**：git 工作樹 + 全歷史 grep AIza/sk- 零匹配，.gitignore 覆蓋 .env。
- **npm audit 0 vulnerabilities**（69 個依賴）。

### 1. 【High】key 明文 localStorage + 零 CSP = 單點 XSS 即全盤洩漏
- `api-key.ts:20,22` 明文寫入 local/sessionStorage；`index.html` 無 CSP meta；`vercel.json` 無 headers 區塊。
- 攻擊場景：任一依賴被供應鏈攻擊 → 一行 fetch 就把 key 偷走，沒有 `connect-src` 擋 exfiltration。
- 今天沒有洞，但也沒有防線接住下一個洞。

### 2. 【Medium】vercel.json 完全沒有 security headers
- 無 CSP / X-Frame-Options / X-Content-Type-Options / HSTS。可被任意 iframe（clickjacking）。
- 成本極低（vercel.json 加 headers 陣列），沒有理由不加。建議至少：
  `default-src 'self'; connect-src 'self' https://generativelanguage.googleapis.com; frame-ancestors 'none'` + `X-Frame-Options: DENY` + `X-Content-Type-Options: nosniff`。
  （注意 Google Fonts 需放行 fonts.googleapis.com / fonts.gstatic.com。）

### 3. 【Medium】key 以 query string 進 fetch URL
- `gemini.ts:22-23` `?key=${apiKey}` — 不進網址列歷史（fetch 非導航），但明文出現在 DevTools Network 面板，螢幕分享/截圖求助即洩漏。
- 這是 Google 公開 API 給純前端的唯一認證方式，根治需後端代理——屬產品定位層級取捨，非 bug。
- 已確認：全 src 零 console.log，錯誤處理不印含 key 的 URL。

### 4. 【Low】KeyPanel 重開面板把明文 key 寫回 DOM input value（`KeyPanel.ts:16-17`，input 是 type=password，刻意的 UX 設計，風險不變）。

## 四、產品 / UX / 商業

### 最殘酷的商業事實
97 筆手工 prompt 是唯一有價值的資產，但這套資產的**配方**（`gemini.ts:3-10` 的 SYSTEM_PROMPT）完整暴露在前端可讀原始碼裡；prompt 結構高度公式化，任何人把地標名稱+這段公式餵給任何 LLM，5 分鐘可重現 90% 效果。這個工具賣的不是「無法複製的內容」，是「不用自己打字的方便」——而這種方便的價值在 AI 普及的環境裡持續趨近於零。變現路徑：完全沒有（無廣告/pro 版/export 限制/登入）。

### 1. 【High】零可觀測性
- 全 repo grep gtag/plausible/umami/@vercel/analytics/sentry → 零匹配。
- 上線後對「有沒有人用、用哪個功能、AI 生成成功率」完全零數據。所有產品決策都是盲猜。
- 這是其他所有產品問題的前提——連「功能入口該不該上移」都無法驗證。

### 2. 【High】差異化功能全部藏在 97 張卡片牆之後
- index.html 版面順序：AI Generator（:92）、Video Transition（:108）、Route Planner（:131）全排在 97 張卡片之後，nav 沒有錨點連結。最有黏著度的功能放在用戶最不可能捲到的地方。

### 3. 【High】RoutePlanner 拖拉排序：鍵盤完全不可用、觸控大機率失效
- `RoutePlanner.ts:83-108` 只綁 dragstart/dragover/drop 滑鼠事件，無鍵盤替代、無 touch fallback（iOS Safari 對 HTML5 DnD 支援差）。不是體驗打折，是一部分用戶功能直接失效。

### 4. 【Medium】a11y 幾乎為零
- 全 src grep `aria-label|alt=|role=|tabindex` → **零匹配**。唯一及格項是 `lang="zh-TW"`。
- 圖示按鈕只有 `title` 屬性（不等同 aria-label）。

### 5. 【Medium】SEO/分享基礎缺失
- 無任何 og:/twitter: meta tags——分享到 LINE/FB/Discord 是裸連結無預覽卡。
- 無 favicon、無 robots.txt、無 sitemap。有 title 和 meta description（及格）。

### 6. 【Low】UI 語言中英夾雜無章法
- 同一個 Toast 元件：`已收藏`（CardGrid）vs `Route cleared`（RoutePlanner）vs `Please set your Gemini API Key first`（AiGenerator）。section 標題也是中英隨機混用。無 i18n 機制，要進英文市場需大改。

### 7. 【Low】無 README、無 onboarding
- 落地頁直接假設讀者知道「3D 浮雕袖珍模型」這個 MidJourney 社群梗。窄眾定位下可接受，但 repo 連用戶向 README 都沒有。

### 正面
- BYOK gate 做得比一般工具好：不設 key 能用掉 80% 核心價值，AI 功能點擊前就有中文提示（index.html:96），不是事後報錯。
- Responsive 有 768/480 兩級斷點覆蓋主要區塊。
